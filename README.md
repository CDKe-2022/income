# 记账系统 · Ledger

一个跑在 Cloudflare 上的极简记账系统。**说一句话、拍一张账单，就记好一笔账。**

针对手机使用做的：界面是 iOS 风格，禁掉了双指缩放，能像 App 一样用；后端跑在 Cloudflare Workers 上，不花服务器钱。

```
iOS 快捷指令 ──► POST /api/ai ──► AI 识别 ──► D1 数据库
     ▲                                            │
     └──────── 前端 index.html ◄──── GET /api/records
```

## 它长什么样

| 首页 | 记一笔 | 统计 |
|---|---|---|
| 本月支出 / 收入 / 笔数，按天分组的记录列表 | 分类和支付方式都是**点一下就选**的芯片，不用打字 | 环形图看分类占比，柱状图看日/月趋势，可翻月 |

- **首页**：顶部大字号显示本月支出，下面是按天分组的记录（今天 / 昨天 / 9月15日），最多展示最近 60 条，更早的看统计页。
- **记一笔**：金额输入框 + 时间（带「今天」「昨天」快捷按钮）+ 备注 + **分类芯片**（10 类，每类带色点）+ **支付方式芯片**（6 种）。不在预设里的分类可以点「自定义…」手输，最多 10 个字。
- **统计**：环形图（分类占比，点分类可高亮）、日柱状图、月柱状图，三个都能点。左右翻月，翻离本月会出现「回到本月」。空月份有专门的提示卡。

> **统计是在前端算的**，不是调 `/api/stats`。前端会**自动翻页拉全量**（每批 500 条，最多 40 页），
> 在浏览器里聚合。所以浏览器的数字是账本的准确值。只有记录超过 2 万条（40 页 × 500）才可能拉不全，
> 那时页面上会出现 `truncated` 警示条，不会静默出错。要绝对准确仍推荐 `/api/stats`。
>
> `/api/stats` 是给「需要精确统计」或「数据量很大」的场景准备的，直接在数据库里 `GROUP BY`，不受上限影响。目前前端没用它。

## 特性

**后端**

- 三个 AI 后端自动降级，任何一个连不上都能往下退，最差也还有内置规则兜底
- 完全零 Key 也能跑（用 Cloudflare 自带的 Workers AI）
- 中文口语金额识别：`三十八块五`、`两百五`、`一百二` 都能算对
- 北京时间统一处理，不受设备时区影响
- 推理模型的思维链（`<think>` 标签）自动剥离
- `/api/ping` 自检端点，一眼看出配置哪儿没对
- 列表截断时返回 `truncated` 标记，前端会警示「统计可能不完整」，绝不静默少算
- 明确的错误路由提示：把 AI 请求打到 `/api/records` 会提示你改 URL

**前端**

- 纯单文件 HTML，无构建步骤，扔哪儿都能跑
- 芯片式选择器，记一笔基本不用打字
- 本地持久化配置，支持带参数的链接一次配好
- 深浅色**自动跟随系统**（纯 `prefers-color-scheme`，没有手动开关）
- 禁用双指缩放、双击缩放、Ctrl+滚轮缩放，接近原生 App 体验
- 编辑老记录时自动回填自定义分类；切换支出/收入时自动清理不适用项
- 键盘导航与屏幕阅读器支持（`aria-pressed`、`aria-live`）

## 部署

### 1. 建 D1 数据库

Cloudflare Dashboard → **Storage & Databases** → **D1** → 创建数据库，名字随意，比如 `ledger`。

建好后进 **Console** 标签，粘贴建表 SQL 执行：

```sql
CREATE TABLE records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL,
  amount REAL NOT NULL,
  category TEXT,
  occurred_at TEXT NOT NULL,
  note TEXT,
  account TEXT,
  raw_input TEXT
);

CREATE INDEX idx_occurred_at ON records(occurred_at);
```

> ⚠️ **执行位置很重要**：SQL 要贴在 D1 的 **Console** 里，不是终端、不是 Cloudflare 的 Workers 编辑器。终端不认 `CREATE TABLE`，会报「没有这个命令」。

### 2. 部署 Worker

新建 Worker，把 `worker.js` 整个文件内容粘进去，然后配置绑定。

在 **Settings → Bindings** 里加三个：

| 类型 | 变量名 | 值 |
|---|---|---|
| D1 Database | `DB` | 选第 1 步建的数据库 |
| Workers AI | `AI` | 无需填值，选上即可 |
| Secret | `API_TOKEN` | 自己设一个，比如 `my-ledger-2026` |

> Workers AI 绑定**不填变量名也能用** —— 代码会自动找出 env 上任何「名字含 ai + 带 `run()`」的绑定，`/api/ping` 会告诉你它实际叫什么。

改完绑定**必须重新 Deploy 一次**才生效，这是 Cloudflare 的坑。

### 3. 验证

```bash
curl "https://你的worker.workers.dev/api/ping?token=你设的token"
```

返回里重点看这几项（精简版，实际字段更多）：

```json
{
  "ok": true,
  "version": "2026-09-17h",
  "bindings": { "DB": true, "AI绑定": true },
  "AI绑定名": "AI（标准）",
  "workersAi连接方式": "binding",
  "openai兼容": "(未配置)",
  "ai": {
    "AI_PROVIDER": "auto（默认）",
    "文字模型": "@cf/qwen/qwen3.8-27b",
    "视觉模型": "@cf/moondream/moondream3.1-9B-A2B",
    "本次生效顺序": { "文字": "workers → rules", "图片": "workers（图片没有 rules 兜底）" }
  },
  "待办": "都配好了"
}
```

`待办` 字段会直接告诉你还差什么。想真调一次模型确认「不是配好了、是真能用」，加 `&test=1`：

```bash
curl "https://你的worker.workers.dev/api/ping?token=你设的token&test=1"
```

### 4. 部署前端

把 `index.html` 放到任意静态托管（Cloudflare Pages / GitHub Pages / 自己的服务器都行），然后打开它，填两个东西：

- **API 地址**：`https://你的worker.workers.dev`
- **Token**：第 2 步设的 `API_TOKEN`

点「保存并加载」就连上了。

> 更省事的办法：用带参数的链接一次配好，配置写进本地存储后地址栏会自动抹掉。
> ```
> https://你的前端地址/#api=https://你的worker.workers.dev&token=你的token
> ```

## API 文档

所有端点都要求鉴权，两种方式等效：

```
Header:  x-token: <API_TOKEN>
Query:   ?token=<API_TOKEN>
```

### `GET /api/ping`

自检。看线上跑的是哪一版、绑定了什么、下一步该做什么。

| 参数 | 说明 |
|---|---|
| `test=1` | 顺便真调一次模型，确认「不是配好了、是真能用」 |

### `POST /api/ai` · `GET /api/ai`

**核心端点。** 把文字或图片丢进来，AI 识别后自动入库。

| 参数 | 位置 | 说明 |
|---|---|---|
| `text` | body / query | 记账文字，如 `午饭35` |
| `image` | body | base64 图片（可带 `data:image/...;base64,` 前缀，会自动剥） |
| `provider` | body / query | 强制指定后端：`auto` / `workers` / `openai` / `rules` |
| `ai` | query | `provider` 的另一个参数名，等效 |

`text` 和 `image` **至少要有一个**，都没有会返回 400。POST 的 body 必须是合法 JSON（不是的话返回 400，不会当成表单解析）。

```bash
# 文字
curl -X POST "https://你的worker.workers.dev/api/ai?token=xxx" \
  -H "Content-Type: application/json" \
  -d '{"text":"午饭35"}'

# 也可以全塞 query 里（短句直接发，适合快捷指令）
curl "https://你的worker.workers.dev/api/ai?token=xxx&text=午饭35"

# 强制走内置规则（快、不耗额度）
curl -X POST "https://你的worker.workers.dev/api/ai?token=xxx" \
  -H "Content-Type: application/json" \
  -d '{"text":"打车18 微信","provider":"rules"}'
```

成功返回 201：

```json
{
  "ok": true,
  "id": 33,
  "message": "已记账：支出 餐饮 ¥35（微信）",
  "parsed": {
    "type": "expense",
    "amount": 35,
    "category": "餐饮",
    "account": "微信",
    "occurred_at": "2026-09-17T12:30:00+08:00",
    "note": "午饭"
  },
  "ai_raw": "{\"amount\":35,\"category\":\"餐饮\",...}",
  "note": "某一层降级失败的原因（只有失败时才有这个字段）"
}
```

| 字段 | 说明 |
|---|---|
| `message` | **给人看的一句话回执**，直接塞给快捷指令做通知就行 |
| `parsed` | AI/规则解析出的结构，已被采用的那份 |
| `ai_raw` | 模型原始输出（截断到 500 字符），排查识别错误时看这个 |
| `note` | 只在某个降级环节失败时出现，说明「谁挂了、为什么」 |

`message` 的格式是 `已记账：支出 餐饮 ¥35（沙县·微信）` —— 分类在前，金额居中，备注和支付方式用 `·` 连接放在括号里。金额是整数就不带小数（`¥38`），有小数才保留（`¥38.5`）。

### `GET /api/records`

读取记录列表，按 `occurred_at DESC, id DESC` 倒序。

| 参数 | 默认 | 说明 |
|---|---|---|
| `limit` | 50 | 每批条数，**上限 500**（`PAGE_SIZE`）。传再大也只给 500 |
| `offset` | 0 | 跳过前 N 条，用于翻页。负数当 0 |
| `month` | — | 形如 `2026-09`，只看某个月 |

返回体：

```json
{
  "ok": true,
  "count": 500,
  "total": 1200,
  "offset": 0,
  "has_more": true,
  "expense_sum": 316.5,
  "truncated": true,
  "hint": "已达上限 500 条，统计可能不完整；要精确统计请用 GET /api/stats",
  "data": [ /* 记录数组 */ ]
}
```

> **翻页拉全量是前端默认行为**。`has_more` 是权威判据 —— 前端据此循环发
> `/api/records?limit=500&offset=0`、`offset=500`… 直到 `has_more` 为 `false`，
> 把数据捞齐后再渲染和统计。所以浏览器的「本月支出」是全量准确值，不受单次上限影响。
>
> `total` 是**总条数**（`COUNT(*)`），别和 `expense_sum`（支出合计）看混。
>
> `has_more` 比 `truncated` 更精确，`truncated` 只作兼容保留：判定条件是「返回条数 ≥ limit」，
> 翻到最后一页时它才会变 `false`。要准确统计仍推荐 `/api/stats`（数据库里聚合的）。

前端翻页有个安全阀：最多翻 40 页（`MAX_PAGES`），且某页返回空数组就停。真翻到 40 页还没到底，
会把 `dataTruncated` 置 `true` 并在界面上显示警示条 —— 宁可承认算不准，也不静默给出错数字。

### `POST /api/records`

手动新增一条（一般用不到，走 `/api/ai` 更方便）。

```json
{
  "type": "expense",
  "amount": 38.5,
  "category": "餐饮",
  "note": "沙县",
  "account": "微信",
  "occurred_at": "2026-09-17T12:30:00+08:00"
}
```

`occurred_at` 不传则用服务器当前北京时间。

### `PUT /api/records?id=123`

修改一条记录。body 同 `POST`。

> 前端对不支持的接口有降级策略：PUT 返回 404/405 时会退回「先建新、再删旧」。

### `DELETE /api/records?id=123`

删除一条记录。

### `GET /api/stats`

**在数据库里做的聚合统计**，不受列表上限影响，是准确值。

| 参数 | 说明 |
|---|---|
| `month` | 形如 `2026-09`；不传则看全部 |

返回（字段是中英混排的，故意的，方便直接读）：

```json
{
  "ok": true,
  "month": "2026-09",
  "笔数": 4,
  "支出合计": 250.5,
  "收入合计": 500,
  "结余": 249.5,
  "金额缺失条数": 0,
  "分类明细": [
    { "分类": "购物", "金额": 200, "笔数": 1, "占比": 79.8 },
    { "分类": "餐饮", "金额": 38.5, "笔数": 1, "占比": 15.4 },
    { "分类": "交通", "金额": 12, "笔数": 1, "占比": 4.8 }
  ],
  "按月汇总": [
    { "月份": "2026-09", "支出": 250.5, "收入": 500 },
    { "月份": "2026-08", "支出": 66, "收入": 0 }
  ]
}
```

`按月汇总` 只在**不传 `month`**（查全部）时返回，最多 24 个月，用于画趋势图。
`占比` 是相对**当月支出合计**算的百分比。
`金额缺失条数` 是 `amount` 为空的记录数 —— 用来提示你去补。

## AI 解析：三级降级链

```
                    ┌─ 文字 ─► Workers AI ─► OpenAI 兼容 ─► 内置规则
POST /api/ai ──────►│
                    └─ 图片 ─► OpenAI 兼容 ─► Workers AI ─► （无兜底）
```

排在前面**没配置或调用失败**，就自动往下退。体验上你只需要知道：**能上网就一定能记账，最差的情况用内置规则也认得出来。**

### A. Workers AI（推荐）

Cloudflare 自带的 AI，**不需要任何 API Key**，绑上就能用。

- 绑定：`Settings → Bindings → Add → Workers AI`，变量名填 `AI`
- 名字写错也能用：代码会自动识别 env 上任何「名字含 ai + 带 `run()`」的绑定
- 不想用绑定，也可以配 `CF_ACCOUNT_ID` + `CF_API_TOKEN` 走 REST 接口，同样是 Cloudflare 自家的 AI
- 想换模型：设 `WORKERS_AI_TEXT_MODEL` / `WORKERS_AI_VISION_MODEL`

### B. OpenAI 兼容接口

ChatGPT、豆包、各类中转站都归这里。

| 变量 | 说明 |
|---|---|
| `OPENAI_API_KEY` 或 `DOUBAO_API_KEY` | 密钥 |
| `OPENAI_MODEL` 或 `DOUBAO_MODEL` | 模型 ID |
| `OPENAI_BASE_URL` 或 `DOUBAO_API_URL` | 接口地址，填到 `/v1` 即可，会自动补 `/chat/completions` |

> 新模型不认 `max_tokens`、只认 `max_completion_tokens` 时，代码会自动换字段重试一次。普通模式留了 800 tokens，推理型模型光思考就能吃掉几百，给少了会把 JSON 截断。

### C. 内置规则解析

零配置、不联网、不耗额度，**纯文字兜底**。

- 能认：金额（含中文口语）、时间、分类、支付方式、备注
- **认不了图片** —— 图片要 OCR，必须靠 A 或 B，或者让快捷指令先用「从图像中提取文本」

### 强制指定后端

两个地方都能设，优先级：**请求参数 > Worker 环境变量 > auto**

```bash
# 快捷指令端
POST /api/ai  body 里加  {"provider":"workers"}
GET  /api/ai?token=xxx&provider=workers&text=午饭35

# Worker 端（环境变量）
AI_PROVIDER = auto | workers | openai | rules
```

| 值 | 解析顺序 |
|---|---|
| `auto`（默认） | 文字：workers → openai → rules；图片：openai → workers |
| `openai` | openai → workers → rules |
| `workers` | workers → openai → rules |
| `rules` | 不调 AI，直接内置规则（最快，但图片解析不了） |

**别名（大小写不敏感）**：

| 写法 | 等价于 |
|---|---|
| `chatgpt`、`gpt`、`doubao`、`ark`、`豆包` | `openai` |
| `worker`、`cf`、`cloudflare`、`workersai` | `workers` |
| `rule`、`local`、`none`、`规则` | `rules` |

「选了谁」只决定**谁先上**，不会锁死。排在前面的没配置或调用失败，照样按原逻辑往下退。写错的名字（比如 `provider=chatgpt2`）会被忽略并按默认顺序走，同时在返回的 `note` 里告诉你。

## 内置规则解析能认什么

这部分是兜底，但打磨得比较细。

### 金额

按优先级往下试，**8 条规则，命中即返回**：

| # | 规则 | 例子 |
|---|---|---|
| 1 | 账单字段名（最可靠） | `支付金额：¥38.50`、`实付 38`、`合计38.5` |
| 2 | 货币符号 | `¥38.5`、`￥38` |
| 3 | 数字 + 块/元 + 角 | `38块5` → 38.5、`38元5角` → 38.5 |
| 4 | 中文数字 + 块/元 | `三十八块五` → 38.5、`两百五` → 250 |
| 5 | 数字 + 元/块/圆 | `38元`、`200块` |
| 6 | 动词附近的数字 | `花了38`、`收到工资 12000` |
| 7 | 动词附近的中文数字（可无单位） | `买水果花了两百五` |
| 8 | 纯兜底：剔掉日期时刻后的唯一数字 | `8月31号晚上聚餐 380` |

几个细节：

- 支持 `万`、`千`、`百` 进位
- 中文数字**缺主语也认**：`两百五` = 250、`一百二` = 120
- **规则 6/7/8 有 10 元下限**（`FALLBACK_AMOUNT_MIN`）。踩过的坑：早先容差给到 8 个字符，`买了两件衣服，第 3 单` 里的 `3` 会被捞出来当金额。现在收紧到 4 个字符并加了阈值。
- 代价是：这条兜底路径上「3 块钱的葱」会被拒。但那种写法通常带单位（`3块`），会先被规则 3/5 命中，不受影响。
- 金额字段名和 `¥` 符号优先于一切 —— 有它们出现就说明这是账单，直接采信。

### 时间

| 类型 | 写法 |
|---|---|
| 相对日 | `今天`、`昨天`（`昨晚` / `昨儿` / `昨日`）、`前天`、`大前天`、`明天`（`明晚` / `明日`） |
| 完整日期 | `2026年9月15日`、`2026-09-15`、`2026/09/15`、`2026.09.15` |
| 月日 | `9月15日`、`9月15号` |
| 时刻（冒号） | `12:30`、`12：30` |
| 时刻（中文） | `3点`、`3点半`、`下午3点`、`晚上8点30分` |
| 时段词 | 早上、早晨、上午、中午、下午、傍晚、晚上、夜里、凌晨、半夜、深夜 |

几个细节：

- **12 小时制会自动补正**：`下午3点` → 15:00，`晚上8点半` → 20:30
- 时段词单独出现时也能用：`昨晚` → 昨天 20:00 左右
- 都没写就用当前北京时间

### 分类

## iOS 快捷指令配置

这是日常最常用的入口 —— **锁屏下拉说一句话就记完了。**

### 文字记账

1. 新建快捷指令，添加「**听写文本**」动作
2. 添加「**获取 URL 内容**」：
   - URL：`https://你的worker.workers.dev/api/ai?token=你的token&text=` 后面接听写结果变量
   - 方法：`POST`
3. 打开「显示更多」→ 请求体选 `JSON`，加一个字段 `text`，值为听写结果
4. 加「**显示通知**」或「**朗读文本**」，内容填返回的 `message` 字段

**说「午饭三十五」，通知弹「已记账：支出 餐饮 ¥35」。**

### 图片记账

关键点：**图片要 base64 之后放在 JSON body 里传**，不要用表单。

1. 添加「**选择照片**」
2. 加「**编码为 Base64**」（或者用「从图像中提取文本」先 OCR，再把文字传过去 —— 后者更省额度）
3. 「获取 URL 内容」→ URL 填 `https://你的worker.workers.dev/api/ai?token=你的token`
4. 方法 `POST`，请求体 `JSON`，加字段 `image`，值为第 2 步的 Base64 结果

> **常见坑**：如果返回 `{"error":"not found"}`，多半是端点写错了。AI 识别是 `/api/ai`，不是 `/api/records`。Worker 检测到你往 `/api/records` 发 `text`/`image` 字段时会明确提示你改。

## 数据表结构

只有一张表。

```sql
CREATE TABLE records (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  type        TEXT NOT NULL,      -- 'expense' | 'income'
  amount      REAL NOT NULL,      -- 金额，正数
  category    TEXT,               -- 分类，如 '餐饮'
  occurred_at TEXT NOT NULL,      -- ISO8601 带 +08:00，如 '2026-09-17T12:30:00+08:00'
  note        TEXT,               -- 备注
  account     TEXT,               -- 支付方式，如 '微信'
  raw_input   TEXT                -- 原始输入，便于回溯「AI 当时看到了什么」
);
```

几点说明：

- **`occurred_at` 统一存北京时间**，带 `+08:00` 后缀。前端和后端都按这个约定解释，不受设备时区影响。
- **`raw_input` 别删**。AI 识别错了的时候，看一眼原始输入就知道是模型的问题还是输入本身有歧义。
- 月份查询用 `occurred_at LIKE '2026-09%'`，所以格式必须规整。

## 前端配置

配置存在 `localStorage` 的 `ledger_cfg_v1` 键下：

```json
{ "api": "https://你的worker.workers.dev", "token": "你的token" }
```

三种写入方式：

1. **手动填**：首次打开会进配置页，填 API 地址和 Token
2. **带参数的链接**（推荐）：`#api=...&token=...`，写入后地址栏自动抹干净
3. **改地址栏参数**：同上，支持 `?` 和 `#`

> 保存前会校验 API 地址必须是 `http://` 或 `https://` 的合法绝对地址。`javascript:`、`data:` 这类伪协议会被挡掉。
> 启动时也会校验已存的配置 —— 早期版本存下的非法地址会被清掉并提示重新填写。

## 安全提醒

- **Token 别泄露**。这个 token 是唯一凭证，任何拿到它的人都能读写你的账本。
- **别在公用设备保存配置**。`localStorage` 是明文的，设备被人拿到就等于账本被人拿到。
- **建议定期换 Token**。改完记得同步更新快捷指令里的 URL。
- **别把 `index.html` 连同 token 一起公开**。带参数的链接 = 带凭证的链接。
- 想更安全的话，可以给 Worker 加 IP 白名单，或者把 `/api/*` 套在 Cloudflare Access 后面 —— 但那样快捷指令就拿不到数据了，需要权衡。

## 前端行为细节

这些是给自己人（和未来的自己）看的，出问题时知道该往哪儿翻。

### 时间一律按北京时间

代码里不调用设备的时区接口，全部走 `bjParts()` —— 用 `Date.UTC` + 固定 `+08:00` 偏移算出来。
设备切到东京（UTC+9）也不会让记录漂到前一天。`datetime-local` 输入框拿到的是「裸本地时间」字符串，
直接拼 `+08:00` 存库，**不要**先 `new Date()` 再取 `getHours()` —— 那个取的是设备本地小时。

### 金额用「分」做整数运算

`toCents` / `fromCents` 把金额在算的时候转成整数分。`0.1 + 0.2 !== 0.3`，
一千笔 0.1 直接累加会得到 `99.9999999999986`。走分运算则精确。
金额为 `null` 的记录（AI 没认出来、等用户补）会**跳过不计**，当成 0 会让统计看起来对了但其实是错的。

### 列表渲染有并发防护

`load()` 里用 `loadSeq` 自增序号，回来时 `if (seq !== loadSeq) return;` —— 连点刷新时，
先发的旧响应不会覆盖后发的新结果。日期分组用 `Map` 而不是「和上一条比」，
后端返回乱序数据时不会拆成一堆碎片组。

### 请求 20 秒超时

`api()` 里挂了 `AbortController`，超时翻成人能看懂的话。超时拦截器包成了 `armTimeout`，
测试里能注入 0.8 秒的版本，不用干等 20 秒就能验证这条路径。

### Token 与链接

配置页的 Token 框是 `type=password`，旁边有「显示/隐藏」。**带参数的链接只写 `api`，不写 `token`** ——
地址栏会被截图、会被分享、会留在浏览记录里。原先的「复制专属链接」按钮已删除，因为它会把 token 拼进 URL。

## 故障排查

**`{"error":"not found"}`**

路径写错了。AI 识别是 `/api/ai`，读列表是 `/api/records`。注意别把 `/api/ai` 写成 `/api/`.

**`{"ok":false,"error":"unauthorized"}`**

Token 不对。检查请求里的 `token` 参数或 `x-token` 头，和 Worker 环境变量里的 `API_TOKEN` 是否一致。

**SQL 报「没有这个命令」**

建表 SQL 贴错地方了。要贴在 D1 的 **Console** 里，不是终端。

**改了绑定不生效**

Cloudflare 要求改完绑定**重新 Deploy**，光保存不算。

**图片识别不了**

内置规则认不了图片。检查 `/api/ping` 看 Workers AI 或 OpenAI 配好了没。

**统计数字偏小**

记录数超过列表上限了。看统计页有没有 `truncated` 警示条，改用 `/api/stats` 拿准确值。

**月份箭头点不动**

早期版本的 bug，已修复。现在只要账本里有记录就能自由翻月，翻离本月会出现「回到本月」按钮。

**手机上双指会把页面放大**

已通过 viewport + CSS `touch-action` + JS 手势拦截禁用。如果你用的是旧版本前端，更新 `index.html` 即可。
